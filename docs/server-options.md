# 重い処理をサーバーに移す検討

作成日: 2026-09-17

## 背景

いまはブラウザが音声のデコード、MP3への変換、分割まで担当しているため、長い録音ほどタブのメモリとCPUを多く使う。こうした処理は本来アプリケーションサーバーが受け持つことが多いので、Vercel以外のデプロイ先も含めて検討する。

## いまブラウザでやっている重い処理

| 処理 | 場所 | サーバーに移せるか |
|---|---|---|
| 録音・録画そのもの（MediaRecorder） | `app/page.tsx` | ❌ マイクと画面はブラウザでしか取れない |
| 録画データをメモリに溜める（720pで1時間約450MB） | `app/page.tsx` | △ 録画しながら少しずつアップロードすれば減らせる |
| 音声のデコード（1時間で約230MBのFloat32） | `lib/audio.ts` の `decodeToMono` | ✅ |
| MP3エンコード（lamejs、CPU負荷が高い） | `lib/audio.ts` の `convertToMp3` | ✅ サーバーのffmpegの方が速い |
| Whisper用にWAVへ分割 | `lib/audio.ts` の `prepareFromSamples` | ✅ |

### ポイント

- メモリを一番使うのは**録画データを溜めること**で、これはサーバーを変えても解決しない。
- デコード、MP3変換、分割はサーバーに移せる。
- 音声は処理の前にVercel Blobへアップロードしている（`backupToBlob`）。サーバーはそのURLから取得して処理すればよく、「まず原本を保存する」流れは崩れない。

### Vercelのままでは難しい理由

Vercel Functionsでもffmpegは動く。ただしHobbyプランは実行時間の上限が約300秒なので、1時間の音声を分割して文字起こしまで終えるには足りない可能性が高い。

## おすすめ構成

### 案A: 画面はVercelのまま、重い処理だけCloud Runに切り出す（推奨）

```
ブラウザ ──録音──> Vercel Blob（原本を保存）
   │
   └─ Blob URL を送信 ─> Cloud Run（ffmpegで分割・MP3化 → Whisper → 結果を返す）
```

- Next.js、ログイン、Blobアップロードは今のまま使える
- 1時間の音声でも60分のタイムアウトに収まる
- 使わない時間は課金されない

### 案B: Oracle Cloud Always FreeのVPSにすべて載せる

- Next.jsとffmpegを1台のサーバーで動かす
- サーバー構築そのものを学ぶ目的なら、こちらの方が学びが多い
- OSの更新、HTTPS化、プロセスの監視も自分で行う必要がある

## あわせてやりたいこと: 録画中の分割アップロード

どのサーバーを選んでも、**録画中に数分ごとにアップロードする**仕組みは入れておきたい。

- 録画データをタブのメモリに溜めなくて済む
- タブが落ちても、アップロード済みの分は残る（2026-08-17の録音消失事故の再発防止になる）
